# Faultline
### Fault-Tolerant Distributed Job Execution Engine

Faultline is a learning-focused backend engineering project written in Go. The goal is to build a fault-tolerant distributed job execution engine where clients can submit jobs, PostgreSQL persists them, a scheduler assigns them to independent workers, and the system recovers jobs when components fail.

The project explores backend development, concurrency, distributed coordination, reliability, and fault recovery.

**Project status:** Early development — API and basic PostgreSQL integration implemented.

## Current Implementation

The initial version provides a Go REST API backed by PostgreSQL.

Implemented features:

- HTTP server running on `127.0.0.1:8080`
- Job submission through a REST endpoint
- Request validation and JSON handling
- PostgreSQL connection pooling using pgx
- Persistent job insertion
- Retrieval of all stored jobs
- Retrieval of individual jobs by ID
- Separate development and test databases
- Automated handler and database integration tests

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/jobs` | Submit a new job |
| GET | `/jobs` | Retrieve all jobs |
| GET | `/jobs/{id}` | Retrieve a job by ID |

### Submit a Job

**Request**

`POST /jobs`

```json
{
  "name": "Email Report",
  "priority": 3
}
```

**Successful response — 201 Created**

```json
{
  "id": 1,
  "name": "Email Report",
  "priority": 3
}
```

The ID is generated by PostgreSQL.

### Retrieve All Jobs

`GET /jobs`

Returns the jobs stored in PostgreSQL.

### Retrieve a Job by ID

`GET /jobs/1`

Returns the matching job or an appropriate HTTP error response.

## Database

The current implementation uses PostgreSQL with the following table:

```sql
CREATE TABLE jobs (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(255) NOT NULL,
    priority INTEGER NOT NULL
);
```

Two databases are used during development:

- `faultline` — development data.
- `faultline_test` — automated test data.

## Running Locally

### Prerequisites

- Go
- PostgreSQL
- Git

### Configure the database

Create a PostgreSQL database named `faultline` and configure the `DATABASE_URL` environment variable.

Example connection string:

```text
postgres://postgres:YOUR_PASSWORD@127.0.0.1:5432/faultline
```

Replace `YOUR_PASSWORD` with your local PostgreSQL password. Do not commit credentials to GitHub.

Create the `jobs` table using the SQL shown above.

### Run the application

```powershell
go mod tidy
go run .
```

The server starts at:

```text
http://127.0.0.1:8080
```

### Run tests

```powershell
go test -v
```

The test configuration uses the separate `faultline_test` database. The test database must have the required `jobs` table.

## Planned Architecture

The intended system will consist of four primary components:

1. **Client/API:** Accepts job submissions and provides job information.
2. **Scheduler:** Selects jobs, manages priorities, assigns work, and monitors execution.
3. **PostgreSQL:** Stores job state, assignments, leases, retries, and execution history.
4. **Workers:** Independent Go processes that execute assigned jobs and report results.

Workers will communicate with the scheduler through gRPC.

## Reliability Goals

The completed system aims to explore:

- Persistent job execution state
- Priority-based scheduling
- Independent and concurrent workers
- Lease-based job ownership
- Heartbeat monitoring
- Recovery after worker failure
- Retry policies and exponential backoff
- Idempotency and duplicate execution handling
- Scheduler leader election
- Automated distributed failure testing

The intended delivery guarantee is **at-least-once execution**, with idempotency mechanisms to protect supported operations from duplicate side effects. Universal exactly-once execution is not claimed.

## Project Scope

Faultline is being developed as a local, resource-conscious project without requiring paid cloud infrastructure.

The initial scope deliberately excludes Kafka, Kubernetes, Redis, multi-region deployment, and AI integrations. The focus is on understanding and implementing the core distributed systems concepts using Go and PostgreSQL.
